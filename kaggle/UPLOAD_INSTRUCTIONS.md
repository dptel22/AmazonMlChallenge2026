# Kaggle upload & run — exact steps (single-notebook flow)

The notebook `kaggle/kaggle_pipeline.ipynb` is FULLY SELF-CONTAINED: every
pipeline function is inlined into its cells (generated by
`kaggle/build_notebook.py` from `code/business_entity_resolution/src/`), so the
payload dataset needs NO code. `src/` is no longer required in the dataset —
existing uploaded datasets that contain `src/` are fine, it is just unused.

## 1. Build the payload (local, ~2 GB)

```powershell
.venv\Scripts\python.exe kaggle\make_dataset_payload.py
```

The notebook only needs these entries in `kaggle_payload/`:

```
kaggle_payload/
├── dataset/train/*.tsv     raw TSVs (train_source1/2/3 + train_ground_truth)
├── dataset/test/*.tsv      raw TSVs (test_source1/2/3)
├── ground_truth.tsv        copy of train ground truth
└── val_s1_ids.txt          THE 18% val split (random_state=42)
```

(The builder currently also packs `src/`, `stages.py`, `utils/`, README/docs —
unused by the notebook, harmless to leave in.) Note: the notebook copies ground
truth from `dataset/train/train_ground_truth.tsv` and regenerates the val split
with the same `random_state=42`, so the top-level `ground_truth.tsv` /
`val_s1_ids.txt` are belt-and-braces — the split is identical on a full run.

## 2. Create / version the dataset — Legacy API key auth

- Auth: `kaggle.json` at `~/.kaggle/kaggle.json` (kaggle.com → Settings →
  Create New Token → legacy API token). **KGAT tokens 403 on dataset version
  commits** (CreateDatasetVersion) — `datasets create` may succeed but the
  version commit fails; documented, use legacy auth.
- New dataset:
  ```powershell
  kaggle datasets create -p kaggle_payload --dir-mode zip
  ```
- Update an existing dataset:
  ```powershell
  kaggle datasets version -p kaggle_payload --dir-mode zip -m "payload refresh"
  ```
- Wait for the dataset page to finish processing, then verify:
  `kaggle datasets status <username>/ber-pipeline` → ready.

## 3. Import the notebook

kaggle.com → Code → New Notebook → **File → Import Notebook** → upload
`kaggle/kaggle_pipeline.ipynb` → Settings: Accelerator = **None (CPU)**,
Internet = **Off** (fair-play: proves no external lookups) → Add Input →
attach your `ber-pipeline` dataset. The notebook finds the mount recursively
(handles `dataset/train` + `dataset/test` and flat layouts).

## 4. Run the notebook

1. **Cell 0 (deps):** uses Kaggle's preinstalled numpy/pandas/lightgbm and
   installs ONLY missing modules. **Never pin versions** — a pinned numpy was
   binary-incompatible with the image's scipy and killed the lightgbm import
   (documented history).
2. **CONFIG cell knobs:** `SAMPLE_N` (>0 = small-slice end-to-end test; 0 =
   full run), `TOPK`, `PROXY`, `NEG_RATIO`.
3. Run stages **A → H in order** (each stage skips if its outputs already
   exist).
4. **Stage B** prints the recall@K table (K × proxy × caps, both mean and max
   proxies). Set `TOPK` / `PROXY` from that table, then run C → H.
5. Stage E (adversarial gate) and **Stage G** (test inference + inline
   validator) must print **PASS**.
6. **Stage H** writes `kaggle_return.zip` (`output/*.tsv` + `model.txt` +
   `model_config.json`) — download it.

Interruptions / 12h cap: every stage is skip-if-done — re-open a session and
re-run from the last completed cell. To bridge sessions, attach the previous
session's `/kaggle/working` output as a dataset input.

## 5. Back home

```powershell
# unzip kaggle_return.zip into repo work/ + output/, then re-verify locally:
.venv\Scripts\python.exe student_resource\utils\validate_submission.py `
    --matching output\matching_results.tsv --candidate output\candidate_pairs.tsv `
    --test-dir student_resource\dataset\test
.venv\Scripts\python.exe code\business_entity_resolution\tests\check_outputs.py `
    --matching output\matching_results.tsv --candidate output\candidate_pairs.tsv `
    --test-dir student_resource\dataset\test
```
Note: the local validator run with `--candidate` will load the full candidate file
into memory (several GB) — if it OOMs, rely on the streaming `check_outputs.py`
(it verifies row coverage, dup ids, and matches ⊆ candidates without materializing
the whole file). On Kaggle, Stage G already ran the inline validator but not a
full candidate materialization; the subset invariant is enforced at write time
and re-proven by check_outputs.py locally.
Then fill Documentation_template.md PENDING slots (recall@K, F_0.5, buckets) and
build `<team>_submission.zip` per RELEASE_CHECKLIST.md.
